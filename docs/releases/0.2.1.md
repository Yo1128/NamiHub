# NamiHub 0.2.1

Windows 桌面端、命令行主机与 Dart SDK 的维护版本。HTTP API 保持 v1。现有资料库和设备配对可继续使用。

## 桌面端

- 换目录时先完成新目录的检查与索引。取消选择、重选当前目录、或打开不可用的目录时，正在运行的共享继续提供服务。
- 首页把搜索和分类放在文件列表旁。同名文件显示各自的目录。配对窗口优先显示八位码，手动连接的地址和证书指纹可按需展开，失效的码会从界面撤下。
- Windows x64 ZIP 从 14,108,574 字节缩至 12,192,363 字节，减少 13.58%。桌面包换用一段 30 秒的轻量视频示例，并随包提供程序实际加载的三个 Visual C++ 运行库。联调包继续使用原来的五个固定样本。

## 主机与 SDK

- 扫描和校验文件内容在后台 isolate 执行。索引成功后一次替换目录，单次失败保留上次可用结果。分页复用排序结果，按游标查找起点。
- 下载重试时持续锁定目标文件，避免两个版本交错写入。目标文件无法创建时直接报告磁盘错误。
- 在同一台 Windows x64 电脑上，以 2,048 个文件分别遍历全部文件、书籍和视频，每页 32 项，合计 128 页。两轮预热、五轮交错测量后，进程内分页中位耗时从 15.051 ms 降到 0.289 ms。计时范围仅包含分页与结果收集。

## 验收

静态分析、目录和下载专项回归、四项桌面控件测试均通过。Windows 原生窗口完成筛选、八码配对、托盘隐藏与恢复、设备撤权。最终桌面 ZIP 在中文路径解压后，用隔离的用户目录连续启动两次，五个示例文件和资料库标识保持一致，两次均正常退出。

0.2.0 SDK 已连接 0.2.1 主机，核对五个文件的摘要，读取视频指定的 4,096 字节并完整下载中文 TXT。本轮使用同一台 Windows 电脑上的独立进程。桌面 EXE 未做 Authenticode 签名，跨两台实体设备的发现和全新 Windows 系统安装仍待现场验收。
